== Introduction

This report records the results of the tests specified in TS-DISP-002 for the display node
(Node 0x10) firmware, including all defects and open items found while testing together with the
main controller (Node 0x04).

=== Key Findings

* 17 defects were found: 2 Critical, 11 Major,
  4 Minor. 14 concern the display (one jointly with Node 0x04) and are raised in
  Jira as ORPT-156 to ORPT-169; 3 concern Node 0x04 (N04-01 to N04-03) and are handed to the
  Node 0x04 team for raising in their tracker.
* The CANopen interface (heartbeat, NMT, RPDO, TPDO, SDO server) and the nominal workflow on the
  bench passed on the development build.
* The CAN logger passed all host test scenarios on the release candidate source.
* The automated unit tests of all display middleware and application modules (137 test cases) passed
  except UT-COAPP-RESET-001, which reproduces ORPT-164 on the PC and confirms its cause.
* Open defects on the operator interface affect data entry (organ details, weight), setpoint
  confirmation and alarm acknowledgement.
* Node 0x04 issues block a reliable start-up when Node 0x04 is powered before the display
  (N04-02) and keep high temperature / pressure alarms active (N04-01).
* 18 open items list missing features and requirement updates (manual flush, PIN, RTC,
  Safe Mode reason, battery data, SWRS baseline).

=== Module: mw_can - FDCAN1 Middleware

==== Overview

`mw_can` wraps FDCAN1 (classical CAN 2.0B, 500 kbit/s) with the STM32 HAL and fulfils the `can_if.h` PIF contract through `MW_CAN_If`. It rejects every frame that matches no filter, gives each registered RX object its own hardware filter, drains the shared RX FIFO0 in the interrupt with a 16-frame budget, counts bus-off events and reports every RX/TX frame to an optional monitor (the SD card CAN log). The test replaces the HAL FDCAN driver with a fake that records every call and holds a scripted RX FIFO.

=== Module: mw_osif - OS Abstraction

==== Overview

`mw_osif` is the thin OS layer over CMSIS-RTOS2 / FreeRTOS used by `CO_driver.c` and the CANopen tasks: mutexes, critical sections, the millisecond tick, fixed-rate delays, a nestable interrupt lock and a memory barrier. It provides the `time_if.h` and `irq_if.h` contracts (`MW_OSIF_TimeIf`, `MW_OSIF_IrqIf`). The test replaces CMSIS-RTOS2, the FreeRTOS critical section macros, `HAL_GetTick()` and the Cortex-M intrinsics with recording fakes.

=== Module: can_log - SD Card CAN Logger

==== Overview

`can_log` copies every RX/TX frame into a 1024-entry RAM queue from the CAN interrupt (monitor callback) and, in the SD task, writes them as CSV lines with a chained CRC-16 to IDLE files and session files. A session file opens when Node 0x04 leaves IDLE (TPDO1 0x181, byte 0) and ends with an END line when it returns to IDLE; a power cut mid-session continues as `_PART<n>`. The test uses fake platform services and an in-memory FatFs with fault injection. The end-to-end file scenarios remain in TC-HST-001..006 (TS-DISP-002).

=== Module: sd_card - SD Task

==== Overview

=== Module: usb_drive - USB Log Copy

==== Overview

`usb_drive` mounts a USB stick after 0.5 s of steady ready state and, while Screen 18 allows it, copies every `*.CSV` in the SD root that the stick does not already have with the same size into `1:/ORGPORT_LOGS/`, except the file being logged. Copying is done in 8 KB chunks with a 40 ms budget per SD task cycle, each file is size-checked after closing, and the copy ends DONE, FAILED, CANCELLED (Cancel button) or ABORTED (stick pulled out). The test uses fake platform services, an in-memory FatFs with fault injection and stubs for the SD card and the logger's open file name.

=== Module: canopen_app and CO_driver - CANopen Start-up and Target Driver

==== Overview

`canopen_app` runs the CANopenNode v4 init / reset-communication sequence for Node 0x10. `CO_driver.c` is the CANopenNode target driver: it maps each CANopenNode RX object to its own hardware filter through the PIF CAN interface (16 slots, dispatched by trampolines), sends through the PIF transmit with overflow handling, and implements the CANopenNode locks with `mw_osif`. The test builds the real CANopenNode v4 library and the generated `OD.c` for the host. The PIF CAN interface (`MW_CAN_If`) is a fake that behaves like `mw_can.c` (16 filters, no registration after start), and `mw_osif` is a fake. Only the Cortex-M `dmb` barrier is replaced, by a host wrapper header that includes the real `CO_driver_target.h`.
