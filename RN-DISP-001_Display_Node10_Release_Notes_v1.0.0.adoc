== Overview

Release v1.0.0 is the first release of the display firmware with the complete system
integration. The previous version was a stand-alone GUI with no communication. This release adds:

* CANopen communication with the main controller (Node 0x04), driving all 18 screens from the
  controller's workflow state and sending operator inputs back;
* alarm handling with an alarm centre, critical popups and operator decision popups;
* CAN traffic logging to the microSD card, one CRC-protected file per session;
* copying of the session logs to a USB pen drive at the end of a session;
* firmware restructured to the CIOET coding guidelines and the platform-interface / middleware /
  application layering.

== New Features

=== CANopen Integration with the Main Controller (Node 0x04)

* CANopenNode v4 on FDCAN1, node 0x10, 500 kbit/s; heartbeat produced every 500 ms; Node 0x04
  heartbeat supervised with a 600 ms timeout.
* Goes Operational by itself when the Node 0x04 heartbeat reports Operational; no NMT Start
  needed.
* Receives seven PDOs from Node 0x04: workflow state and alarms, temperatures, humidity, bubble and
  level sensors, GPS, debug events, boot health, pressures, pump speed and priming progress.
* Sends operator inputs on TPDO1 0x190: confirm handshake (counter and current state),
  authentication, organ type, preservation mode and organ weight.
* Writes to Node 0x04 by SDO: alarm acknowledge, session resume / abandon, motor diagnosis answer
  (0x2200) and temperature / pressure setpoints (0x2201).
* FDCAN hardware filter rejects all frames that the display does not use.

=== Workflow and Screens

* Every screen follows the Node 0x04 workflow state (IDLE to REPORT); confirms are sent with the
  agreed handshake and the next screen opens only when Node 0x04 has moved on.
* After a display restart during a session, Screen 1 jumps to the screen of the running state.
* Thermal stabilisation (Screen 5) unlocks Continue only within +/-0.5 degC of the target.
* Reservoir fill and priming / bubble detection (Screens 6-7) show the live priming phase,
  cycles, countdowns and pump speed from Node 0x04.
* Dashboard (Screen 15) shows live temperature, pressure, motor status, elapsed and loading time;
  values show `--` when the sensor is faulted or the controller is offline.
* Transport summary (Screen 17) with organ details, temperature and pressure statistics and an
  alarm log.

=== Alarm Handling

* Status bar on every screen with alert count, GPS indicator and a controller-offline banner.
* Alarm centre with one card per active alarm bit; critical alarms in red, warnings in orange.
* Critical alarm popup on the dashboard.
* Decision popups for motor diagnosis (bit 16), session resume (bit 18) and pressure range
  (bit 19), with a confirmation step for irreversible answers.

=== SD Card CAN Logging

* Logs every frame the display receives and sends, as CSV with line number, time, direction, ID,
  data and a CRC-16 chained from line to line.
* One file per session (SESSION_nnnn_CANLOG.CSV) with a ~4 s pre-roll and an END line; idle
  periods in SESSION_nnnn_IDLE_k.CSV; a session interrupted by a power cut continues in
  _PART2, _PART3 files.
* Data saved at least every 2 s; card removal and missing card do not affect the rest of the
  system.
* PC tool `test/sd_canlog/check_canlog.py` verifies the files.

=== USB Log Copy

* On Screen 18, all session logs are copied to `ORGPORT_LOGS\` on a FAT32 pen drive.
* Files already on the stick are skipped; every copied file is size-checked; nothing is deleted
  from the SD card.
* Progress popup with Cancel; pulling the stick out mid-copy is detected and reported; Power Off
  stays disabled until the copy is finished, cancelled or skipped.

=== Code Quality and Architecture

* Converted to CIOET-ORGPORT-CGD-2026-001 (headers, naming, Allman style, named constants, no
  dynamic memory).
* SD card, USB and CAN logger moved to the platform-interface / middleware / application
  structure; platform services wired in one place (app_wiring.c).
* GUI widgets, handlers and interactions renamed to a consistent naming scheme.

=== Operating Notes for this Release

* Power the display together with or before the main controller (see N04-02).
* High temperature / pressure alarms stay active until acknowledged, even after the value returns
  to normal (N04-01).
* In Screen 13, keep setpoints within 0-15 degC and 0-50 mmHg (ORPT-160).
* Enter digits only in the organ weight field (ORPT-158).
* Use Acknowledge in the alarm centre, not on the dashboard critical popup, to acknowledge an
  alarm (ORPT-161).

== Open Items and Limitations

Features and decisions not included in this release:

[cols="1,2,4",options="header"]
|===
|ID |Item |Description
|OI-01 |Fill phase limited by a maximum time |Node 0x04 ends the fill after a fixed maximum time; required: stop only when the level sensor detects fluid.
|OI-02 |Manual flush from the dashboard |Feature required on Screen 15; needs a flush request object and behaviour in Node 0x04 first.
|OI-03 |Logging of operator entries |Organ details (ID, hospitals, blood type, clamp time) and operator setpoint changes are not in the SD log (only CAN frames are logged).
|OI-04 |Safe Mode reason not shown |0x2190 sub2 (safe_mode_reason) is received but not displayed; awaiting Node 0x04 team decision.
|OI-05 |Clearing a permanent Safe Mode in service |Refrigeration, actuator, motor and pressure-range failures are stored and carried into every boot; no service clear path exists.
|OI-06 |PIN verification not defined |Any 6-digit PIN is accepted; auth_status is always 1; attempt counter and lockout not implemented.
|OI-07 |Screen 1 validation is a wait only |The 'Validating Sensors & Subsystems' popup waits for the Node 0x04 confirm; no readiness status is shown.
|OI-08 |Alarm timestamps |Alarms carry no time of day (needs RTC).
|OI-09 |RTC not integrated |Time of day is not kept across power cycles.
|OI-10 |Screen 17 'Saving History' placeholder |Animation only; no save operation behind it.
|OI-11 |Battery data simulated |Battery level and runtime are simulated; no battery data in the interface.
|OI-12 |Hypothermic (HOPE) option still selectable |HOPE is not used in this release, but Screen 9 still offers Hypothermic Oxygenated Perfusion, which leads to the unused oxygenator Screens 10 and 11.
|OI-13 |Dashboard 'Next Flushing' is display-only |Countdown is computed locally, not from Node 0x04.
|OI-14 |No low temperature / low pressure alarms |Node 0x04 defines no TEMP LOW or PRESSURE LOW bit.
|OI-15 |Emergency stop bit 24 not defined |The display table includes bit 24; the Node 0x04 code does not define it.
|OI-16 |Test bypass macros in Node 0x04 debug build |WORKFLOW_TEST_BYPASS_SENSOR_GATE and the stepper bypass are still in the Node 0x04 build configuration.
|OI-17 |Requirement baseline outdated |CIOET-ORGPORT-SWRS-RVD-2026-001 still describes node 0x06, W25Q128 flash logging, TinyUSB export on SDO trigger, NMT start by Node 0x04 and a five-screen HMI. The implementation uses node 0x10, SD card logging, USB copy on Screen 18, autonomous Operational and 18 screens. The SWRS must be updated.
|OI-19 |No audible alarm |No buzzer is driven on alarm activation (SWRS-M2-HMI-05 item 4).
|===

== Installation

. Build the CM7 project in STM32CubeIDE 1.19.0 (configuration Debug), or use the released binary.
. Connect the ST-LINK and flash the CM7 application with STM32CubeIDE (Run / Debug) or
  STM32CubeProgrammer.
. Insert a FAT32 microSD card and connect the CAN bus to the main controller.
. Power on: Screen 1 shows "Software Version: v1.0.0" and "Hardware Version: HW-1.0".
